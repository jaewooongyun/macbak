# 개발 기록

이름은 한국어 "맥박(脈搏)"을 영문으로 적은 것으로, "맥(Mac)"과 겹쳐 맥의 맥을 짚는다는 뜻입니다. 2026-11-04에 영문 표기를 Maekbak에서 Macbak으로 바꿨습니다. 번들 ID(`local.roomloop.native`)는 그대로라 설정과 정기 정리 기록이 이어집니다.

## 개발용 실행

```bash
open dist/Macbak.app          # 실행 (Apple silicon, macOS 14 이상 · Liquid Glass는 macOS 26 이상)
bash scripts/build-app.sh       # 다시 빌드 → dist/Macbak.app (로컬 서명만, 배포 서명·공증 없음, 디버그 기호 제거)
bash scripts/make-dmg.sh        # 공유용 → dist/Macbak-<버전>.dmg (앱 + Applications 바로가기)
swift test                      # 안전 게이트·실행기·기업 보안 제외·휴지통·시뮬레이터 판정·판정·AI 분류·맥박·예약 테스트 (145개)
dist/Macbak.app/Contents/MacOS/Macbak --snapshot snapshots   # 화면을 PNG로 렌더 (픽스처만, 디스크 정리 대상은 검사하지 않음)
dist/Macbak.app/Contents/MacOS/Macbak --scan-report          # 실제 디스크를 검사해 후보와 판정을 출력 (읽기 전용, 지우지 않음)
```

## 디자인 기준

- **Liquid Glass는 떠 있는 컨트롤에만 씁니다.** 툴바(맥박 알약·새로 고침), 사이드바, 아래에 떠 있는 선택 막대, 정리 패널, 차트 값 표시, 보조 버튼(`.glass`)입니다. 선택 막대를 누르면 캡슐이 패널로 변형됩니다(`glassEffectID`). 떠 있는 막대에는 `safeAreaBar`를 써서 아래로 지나가는 행을 흐리게 하므로 유리 위 글자가 읽힙니다. macOS 26 미만에서는 material로 대체합니다.
- **글자가 있는 카드는 불투명하게 둡니다.** 유리 위에 바쁜 행이 지나가면 글자가 겹쳐 읽히지 않는 것을 실제 창에서 확인했기 때문입니다. 라이트 모드는 흰 카드, 다크 모드는 한 단계 밝은 회색이고 그림자 없이 머리카락 두께 테두리만 둡니다.
- **글자와 숫자:** 시스템 텍스트 스타일만 쓰고, 중요한 값은 13pt 이상입니다. 큰 숫자는 SF Pro Rounded에 고정폭 숫자입니다.
- **색:** 제조사 색(Anthropic 주황·OpenAI 민트·Google 파랑…)은 제조사를 뜻하는 자리에만 쓰고, 나머지는 단색입니다. 상태는 색만으로 구분하지 않고 SF Symbol과 라벨을 함께 씁니다.
- **반응형:** `AdaptiveGrid`가 폭에 맞춰 1~3열로 타일을 놓고, 한 줄의 타일 높이를 맞추며, 줄 끝에 빈칸이 남으면 마지막 타일을 넓혀 채웁니다. 맥박 헤더는 좁으면 세로로 쌓입니다. 창 최소 크기는 760×560입니다.
- **모션:** 끊김 없이 이어지면서 가볍게 만들었습니다. 2초마다 바뀌는 값은 모두 **Core Animation**이 움직입니다. 앱은 새 값을 한 번만 넘기고, 움직임은 화면 서버가 재생합니다.
  - 심전도와 스파크라인은 다음 샘플까지 한 칸씩 계속 흘러갑니다(`LiveLine`).
  - 막대·링·구간 막대는 0.3초 동안 새 값으로 미끄러지고(`LiveShapes`), 숫자는 커지면 아래에서, 작아지면 위에서 밀려 들어옵니다(`RollingText`).
  - 계기판의 작은 퍼센트 숫자는 활성 상태 보기처럼 바로 바뀌고, 그 아래 막대가 부드럽게 따라갑니다.
  - 타일을 누르면 App Store처럼 새 페이지가 타일 자리에서 커져 화면을 채웁니다(`ZoomFromTile`, 0.35초). 커지는 동안은 서리 판(창 배경 90% + 빛 번짐 + 빛 테두리) 아래로 페이지가 은은하게 비치다가, 마지막 구간에서 판이 걷히며 또렷해집니다. 뒤의 페이지는 작아지며 어두운 막 아래로 가라앉고, 새 페이지의 불투명 바탕은 뒤 페이지가 사라지는 장면까지 유지합니다. 바탕과 서리 판은 고정색 `windowBackgroundColor`가 아니라 창 배경 스타일(`.windowBackground`)로 칠합니다. 다크 모드 창은 바탕화면 색이 섞여 푸른 기운이 있는데, 고정 회색으로 칠하면 그 옆에서 초록·올리브빛으로 보였습니다.
  - 사이드바 전환은 흐림을 거쳐 바뀌고(`blurReplace`), 창 폭이 열 수 경계를 넘으면 타일이 스프링으로 새 자리까지 흘러갑니다(`LiquidGrid`).
  - 타일은 포인터를 올리면 살짝 부풀며 가장자리에 빛이 돌고, 누르면 젤리처럼 눌렸다 돌아옵니다.
  - 창이 닫혔거나 가려졌을 때, 메뉴 막대 패널이 닫혀 있을 때는 애니메이션을 끕니다(`animatesOnlyWhenShown`). "동작 줄이기"를 켜면 모두 멈추고 화면도 바로 바뀝니다.

## 성능

화면이 켜진 상태에서 30초(또는 20초) 동안 이 앱이 쓴 CPU입니다. 코어 1개를 100%로 봅니다(2026-11-02).

| 상태 | CPU |
|---|---|
| 한눈에 | 5.1~6.7% |
| 디스크 | 3.4% |
| 메모리 | 6.0% |
| AI 활동 | 7.3% |
| AI 저장 공간 | 3.4% |
| 루프 | 3.5% |
| 창을 닫은 뒤 | 1.0~2.0% |
| 메뉴 막대만 (패널 닫힘) | 1.8~2.2% |
| 메뉴 막대 패널을 연 동안 | 6.9% |

실제 정리 기능을 넣은 뒤(2026-11-03)에는 화면이 잠긴 상태에서만 다시 쟀습니다(3.4~3.6%). 창이 보이는 상태의 값은 아직 다시 재지 못했습니다. 디스크 검사는 약 20초 돌며 그동안 CPU를 씁니다. 처음에는 Xcode 캐시 폴더 약 280개를 하나씩 훑어 114초가 걸렸고, 여러 폴더를 동시에 훑도록(`TreeWalk.inspectAll`) 바꿔 19초가 됐습니다(결과 행 수·판정은 같음).

패널 수치는 이 Mac의 메뉴 막대 아이템이 노치에 가려 열 수 없어서, 같은 `MenuBarPanel`을 임시 패널 창에 띄워 잰 값입니다(메인 창 닫음). 패널을 닫으면 AI 샘플링이 멈춰 1.8~2.2%로 돌아오는 것까지 확인했습니다.

AI 저장 공간을 처음 열면 폴더 검사가 약 20초 돌며 그동안 코어 하나의 40% 정도를 씁니다.

메모리 사용량(phys_footprint)은 약 200 MB이고, 그중 약 114 MB는 창을 그리는 그래픽 메모리입니다. 아직 줄이지 못했습니다. 창을 닫은 뒤 110 MB까지 내려간 적도, 190 MB대에 머문 적도 있어서 반납 시점은 시스템에 달려 있습니다.

재설계 직후 한눈에가 40%였고, 원인을 하나씩 재며 줄였습니다.

1. 프로세스 분류가 경로마다 `URL(fileURLWithPath:)`를 만들어 `lstat`을 수천 번 불렀습니다. 문자열 처리와 한 번 만든 조회표로 바꿨습니다.
2. 2초마다 값이 바뀔 때 붙던 애니메이션(링, 막대, 숫자, 하트, 고리)이 시간을 거의 다 채웠고, 프레임마다 카드 전체(그림자 블러·글자·아이콘)를 CPU로 다시 그렸습니다. 값은 바로 바꾸고, 계속 움직이는 것은 Core Animation으로 옮기고, 카드 그림자를 없앴습니다.
3. AI 감시와 앱 목록 조회는 창이나 메뉴 막대 패널이 화면에 보일 때만 돕니다. 쉬는 순간 값을 비워서, 다시 보일 때 오래된 숫자가 현재 값처럼 보이지 않습니다. 닫혔거나 최소화됐거나 완전히 가려지면 쉽니다. `Window` 장면은 닫혀도 뷰를 버리지 않고 `onDisappear`도 불리지 않아서, 창이 실제로 보이는지를 확인하고, 닫히거나 최소화되면 상세 화면을 빈 뷰로 바꿉니다(닫은 뒤 7.3% → 2.0%).
4. 디스크 용량 조회(최대 0.1초)를 메인 스레드 밖으로 옮겼습니다.
5. 값 애니메이션을 되살렸더니 창이 없어도 38%였습니다. 닫힌 메뉴 막대 패널이 보이지 않는 채로 살아서 2초마다 숫자와 막대를 애니메이션하고 있었습니다. 보이지 않는 창에서는 애니메이션을 끄도록 바꿔 2.0%가 됐습니다.
6. 창이 보이는 한눈에에서도 SwiftUI 값 애니메이션이 28~39%를 썼습니다(끄면 6.0%). 숫자·막대·링·구간 막대를 모두 Core Animation으로 옮겼고, 창이 보이는 상태에서 6.0%로 돌아왔습니다(전환 전 28~39%).
7. 디스크 화면의 "기기 AI가 살펴보는 중" 카드는 기호 하나만 반복해서 깜빡입니다. 처음에는 SwiftUI `symbolEffect(.pulse)`로 만들었다가, 5번·6번과 같은 이유(프레임마다 카드 전체를 CPU로 다시 그림)로 Core Animation 반복 애니메이션(`ExploreGlyphView`)으로 바꿨습니다. 화면 쪽 애니메이션은 카드가 나타나고 사라질 때만 걸고, 항목마다(약 5초) 바뀌는 진행도는 즉시 바꿉니다. 진행도에 걸면 그때마다 주변 카드 셋이 다시 배치되고 그림자가 다시 그려집니다. 탐지는 항목당 약 5초라 항목 4개면 20초 남짓 움직입니다. 2026-11-04 측정(별도 사본, `MACBAK_OPEN_SCREEN=disk`로 디스크 화면에서 시작): 검사 중 앱 CPU 200~880%(여러 코어로 병렬 순회), 기기 AI 탐지 중 약 83%, 안정 상태 6.5%(측정 창이 계속 화면에 있던 실행; 창이 가려졌던 다른 실행은 4.1%). 탐지 중 샘플을 보면 그 83%는 같은 시각에 도는 AI 저장 공간 검사의 트리 순회(코어 하나)이고, 메인 스레드는 탐지 중 2.0%·안정 1.8%만 바빴습니다. 다만 측정 중 사용자가 맥을 쓰고 있어 40초·80초에 측정 창이 화면에 없었습니다. 그래서 "창이 보일 때 맥박 애니메이션 비용"은 확정하지 못했습니다.

## 검증

**렌더:** `--snapshot`이 화면 6개를 라이트·다크로, 라이트는 최소(760×560)·넓은(1680×1000) 창으로도 그립니다. 디스크 화면은 정리 묶음이 모두 보이도록 긴 창(1180×3600)으로도 그립니다(`disk-*-tall.png`). 예시 행에는 세 묶음, 접힌 보호 묶음, 기기 AI 표지, 도구 명령, 탐지 중 카드가 모두 들어 있습니다. 화면 밖 렌더에서는 Liquid Glass와 반투명 효과가 그려지지 않으므로(막대가 투명하게 찍힘), 유리는 실제 창 캡처로 확인합니다. 고대비 외형도 화면 밖에서는 검사할 수 없습니다.

**얕은 정리 범위 확대 뒤 실제 검사 (2026-11-04 오후, 같은 `--scan-report`, 시뮬레이터를 뺀 최종본):** 65.5초. 얕은 정리 23줄 101 GB(Xcode 빌드 캐시 19줄 94.4 GB 가운데 작업 공간 기록이 없는 것 13줄, 기기 지원 파일 1줄 7 GB, 컴퓨터 사용 도구 임시 스크린숏 90 MB, 나머지 2줄은 1~2 MB). 확대 전에는 3줄 94 MB였습니다. 대시보드에서만 미리 체크되는 줄은 3개 2.2 GB로, 조용한 시뮬레이터 1대(1.8 GB)와 macOS 배경화면 동영상(482 MB), `vscode-ripgrep`입니다. 고를 수 있는 줄의 금지 경로 0건, 실행기가 거부할 줄 0개. 열린 파일이 있는 워크트리 하나는 "진행 중인 작업이 사용하고 있습니다"로 남았습니다.

**첫 실제 즉시 정리와 오탐 수정 (2026-11-04 저녁, 사용자가 누름):** 23줄 가운데 11줄을 지웠고 여유 공간이 422.0 GB에서 441.1 GB로 약 19 GB 늘었습니다(정리 기록 `cleanup-log.jsonl`). 나머지 12줄(Xcode 빌드 캐시)은 [정리](cleanup.md)의 "빌드 캐시의 오탐"으로 건너뛰었습니다. 규칙을 고친 뒤 같은 검사에서 얕은 정리는 그 12줄 81.1 GB이고, 검사는 83.6초, 금지 경로 0건, 실행기가 거부할 줄 0개였습니다. 검사 전후 체크아웃 855곳의 `.git/index` 시각은 그대로였습니다.

**두 번째 실제 즉시 정리 (2026-11-04 밤, 사용자가 누름):** 고친 빌드로 14줄을 모두 지웠고 여유 공간이 440.5 GB에서 480.2 GB로 약 40 GB 늘었습니다. 바로 앞의 실행은 14줄 모두 "중단해서 지우지 않았습니다"로 끝났습니다(4초). 이름을 바꾼 뒤 새 앱에서 메뉴를 열자, 디스크 검사가 끝난 16초부터 얕은 정리 칸은 "2개 · 검사 16초 전 · AI 확인 중"과 "즉시 정리 · 19.1 GB" 버튼을 보였습니다. AI 저장 공간 검사(이 Mac에서 49.3초)가 도는 동안에도 인디케이터로 바뀌지 않았습니다. `lsof` 전체 목록은 이 Mac에서 1.24초입니다.

**실제 검사, 얕은 정리와 깊은 정리 (2026-11-04, `--scan-report`가 AI 저장 공간까지 포함):** 얕은 정리 2줄 92 MB(둘 다 AI 도구 카탈로그: MCP 로그, 컴퓨터 사용 도구의 임시 스크린숏). Xcode 캐시 32줄은 모두 3일 안에 썼거나 쓰는 중이라 빠짐. 대시보드에서만 미리 체크되는 줄 3개 486 MB. 고를 수 있는데 실행기가 거부할 줄 0개(시뮬레이터는 `simctl delete`라 경로 가드 밖), 금지 경로 0건. 기기 AI 4개 보고 4개 제안, 거부권 대상(규칙이 모르는 앱 캐시)은 이번에 없음.
